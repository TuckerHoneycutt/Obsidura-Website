Ingest data

/hooks/upload → normalize → catalog → describe
How this pipeline works
A webhook trigger accepts the file; ingest_normalize turns it into kernel-value shape — CSV to Table with profiled columns, JSON to Record, documents and images to content-addressed Files — catalog_register writes it into the catalog, and the describe agent proposes a description and tags that a deterministic step commits.
the catalog
IV

External sources

/hooks/curate → snapshot · cron → liveness
How curation works
Admitting a URL fetches it once through the proxy, under the grant allowlist; the bytes are content-hashed into the blob store and the provenance recorded. Downstream tasks consume the snapshot as an ordinary File — the URL is provenance, never a runtime dependency. The hourly liveness sweep re-probes each entry.
the registry
V

Ask the agent

/hooks/ask → agent_answer
How the agent is bounded
The agent's queryable surface is the ingest catalog, the web registry, and the blob store — an envelope enforced at the proxy under your grant. Within it, the agent chooses what to pull per question, and every call it makes lands in the audit trail below its answer. With no API key it runs the deterministic mock: provider; set PANTHEON_LLM_ANTHROPIC_API_KEY and restart to go live — the model is a string in the definition, not code.
